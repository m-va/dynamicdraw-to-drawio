# svg2drawio — Dynamic Draw 専用の draw.io コンバータ

フリーのドローソフト **[Dynamic Draw](https://dynamicdraw.com/)** で作った図を、
**[draw.io (diagrams.net)](https://www.drawio.com/)** で**そのまま編集できる形式**（`.drawio`）に変換する
Python スクリプトです。Python 3.8 以降と標準ライブラリだけで動きます。

汎用の SVG 変換ツールではなく、**Dynamic Draw の SVG 出力の癖に合わせ込む**ことで忠実度を上げています
（汎用変換については[関連プロジェクト](#関連プロジェクト)を参照）。

画像として貼り込むのではなく、矩形・楕円・コネクタ・テキストといった **draw.io ネイティブの図形**に変換するので、
変換後に色を変えたり、図形を動かしたり、文字を打ち直したりできます。

![変換例](docs/example.png)

## なぜ SVG 経由なのか

Dynamic Draw の保存形式 `.mdpf` は、実体は **PNG ファイル**です。
先頭に 180×180 のサムネイル画像があり、図面データは PNG の私的チャンク **`mdRw`** に
zlib 圧縮された MFC のシリアライズ済みバイナリとして入っています（`.mdpf` を `.png` にリネームすると
サムネイルが見られます）。この最内層は仕様非公開の独自バイナリなので、直接読むのは現実的ではありません。

一方、Dynamic Draw の **SVG 出力**は部品単位でコメントが残る非常に素直な構造をしています。

```xml
<!-- 矩形部品 ID=416 -->
<g id='Group-416'>
  <defs><symbol id='ObjectBody-3'><path d='M 223 241 C ...' /></symbol></defs>
  <use href='#ObjectBody-3' fill='none' stroke='#0000ffff' stroke-width='0.25' ... />
  <text class='sfont-7' fill='#000000ff'><tspan x='313' y='230'>平滑化</tspan></text>
</g>
<!-- End of 矩形部品 ID=416 -->
```

部品種別・ID・色・線種・フォントがすべて読み取れるため、これを draw.io の要素へ機械的に対応付けられます。
本スクリプトはこの SVG を入力にします。

## 使い方

### 1. Dynamic Draw で SVG にエクスポートする

1. **Ctrl+A** で全部品を選択する
2. メニューの **ファイル > 選択部品の画像をエクスポート**
3. ファイルの種類で **SVG** を選んで保存する

> **注意**
> - メニューには **ファイル > エクスポート** もありますが、こちらは「テンプレートの作成などに使う」
>   文書の保存で、画像出力ではありません。画像（SVG を含む）を出せるのは
>   「選択部品の画像をエクスポート」だけです。
> - 名前のとおり**選択された部品だけ**が対象なので、図面全体を変換したいときは Ctrl+A を忘れずに。
> - 文字をパスに変換するようなオプションは無く、常に `<text>` として出力されます。
> - SVG 出力はかつて別売プラグインで提供されていた機能で、現在は本体に統合されています。
>   古い版では SVG が選べなかったり出力に不具合があったりするので、
>   **[最新版の Dynamic Draw](https://dynamicdraw.com/)** を使ってください（フリーソフトです）。

### 2. 変換する

```bash
python svg2drawio.py 図面.svg -o 図面.drawio
```

`-o` を省略すると入力と同じ場所に `.drawio` を作ります。実行すると変換結果の内訳が表示されます。

```
図面.svg -> 図面.drawio
  矩形 88 / 円弧 98 / 線 213 (端点接続 330) / テキスト単体 276 / 図形内ラベル 69 / 変換不能 0
```

### 3. draw.io で開く

draw.io（デスクトップ版 / [app.diagrams.net](https://app.diagrams.net/)）の **ファイル > 開く** から
出来上がった `.drawio` を開きます。

### 同梱のサンプル

上の図がその変換結果です。

```bash
python svg2drawio.py examples/sample.svg -o examples/sample.drawio
```

サンプルはフィードバック制御系のブロック図で、入れ子 tspan（Symbol フォントの τ、上付きの e<sup>-Ls</sup>）、
破線の枠、折れ点のある矢印、複数行の中央寄せラベルなど、変換でつまずきやすい要素をひと通り含んでいます。

### 任意: Pillow を入れると文字の位置がより正確になります

インストールされていれば、Windows のフォントファイル（`msgothic.ttc` など）を使って文字幅を実測し、
寄せ（左寄せ・中央寄せ・右寄せ）の判定とラベル位置の精度を上げます。
無い場合は「全角 1em・半角 0.5em」の概算で動作します。

```bash
pip install pillow
```

## 何がどう変換されるか

| Dynamic Draw の部品 | draw.io での姿 |
|---|---|
| 矩形部品（枠あり） | 矩形シェイプ。塗り・線色・線幅・破線パターンを再現 |
| 矩形部品（枠なし＝文字だけ） | テキストシェイプ。文字の実座標から配置 |
| 丸角矩形部品 | 角丸の矩形シェイプ |
| 円弧部品 | 楕円シェイプ |
| 表部品・グループ部品 | 中の図形を 1 つずつ矩形・楕円・線として展開 |
| 閉じた多角線 | 図形として出力（菱形→菱形シェイプ、六角形などは形を保つステンシル図形） |
| 多角線部品 | **コネクタ**。折れ点（waypoint）・矢印・曲線つき |
| OLE 部品（数式など） | 埋め込み画像。`--ole-latex` を使えば `$$...$$` の数式テキスト |
| 部品内の文字 | その図形のラベル。寄せ方と行間を元図に合わせる |

さらに、変換時に次の処理をしています。

- **端点の自動接続** — 線の端点が図形の枠線上で終わっていれば、その図形に接続します。
  図形をドラッグすると線が追従します（接続点は `exitX/entryX` で固定するので、変換直後の見た目は元図のまま）
- **矢じりの補正** — Dynamic Draw は線本体を矢じりの手前で止めて矢じりを別パスで描くため、
  終点を矢じりの先端まで延長し、実寸を `endSize` に反映します
- **入れ子 tspan の展開** — 書体切り替えや上付き（z⁻¹）は `<sup>` として復元します
- **Symbol フォントの Unicode 化** — `m` → `μ`、`D` → `Δ` などに置換します
  （和文フォントだと全角になってしまうため、該当文字だけ欧文フォントを指定します）
- **単位換算** — SVG のユーザー単位 mm を 96dpi の px に換算し、ページサイズも合わせます
- **UI 言語に依存しない部品判定** — コメントの部品名は Dynamic Draw の表示言語によって変わるため、
  日本語名・英語名のどちらでも判定し、未知の名前だった場合はパスの形（閉じているか、
  四隅が軸に平行か、ベジェ曲線か）から種類を推定します

## OLE 部品（Microsoft 数式 3.0 など）

Dynamic Draw の SVG 出力は、OLE 部品を**表示されない形で書き出します**。

```xml
<symbol id='OleImage-52'><image x='0' y='0' width='0' height='0' href='data:image/png;base64,...' /></symbol>
<use href='#OleImage-52' transform='translate(22.39 14.69) scale(inf, inf)' />
```

`width='0' height='0'` と `scale(inf, inf)` のため、ブラウザや他のツールでは何も描画されません。
数式が消えたように見えるのはこれが原因です。ただし **PNG のデータ自体は無傷で入っている**ので、
本ツールは位置と縦横比から埋め込み画像として復元します。

```
test.svg -> test.drawio
  OLE部品 10 個を埋め込み画像として復元しました(--ole-latex で数式に置き換えられます)
```

### mdpf を渡すと数式に自動変換できる（推奨）

`.mdpf` の中には、OLE の**元データ（MathType の MTEF 形式）**と**部品の外接矩形（mm）**が
そのまま残っています。mdpf を一緒に渡すと、数式を LaTeX に自動変換し、大きさも実寸で配置します。

```bash
python svg2drawio.py 図面_1.svg --mdpf 図面.mdpf
```

SVG は図面の一部を切り出して出力されるため座標系がずれますが、**縦横比の一致する組み合わせで
平行移動量を投票して自動的に対応づける**ので、どのシートの SVG かを指定する必要はありません。

数式の大きさは、**文書全体で 1 つの基準サイズに揃えたうえで、外接矩形に収まらないものだけ縮める**
方式です。組版の見積もりには誤差があるため、既定では枠の 0.8 倍に収めます
（1762 個の数式で実測した結果、この値ではみ出しは 1.6%。大きめにしたい場合は `--eq-margin 0.9`）。基準サイズは各数式が枠に収まる最大サイズの中央値から決めます（LaTeX の組版サイズの
見積もり式は、MathJax で 88 個の数式を実測して係数を合わせてあります）。

### 複数の mdpf をまとめて処理する

パスにフォルダを渡すと、`xxx.mdpf` と `xxx_1.svg, xxx_2.svg, ...`（無ければ `xxx.svg`）を
対応づけ、**シートごとのページを持つ `xxx.drawio`** を書き出します。

```bash
python svg2drawio.py 図面フォルダ/
```

```
図面フォルダ/test2.mdpf: 数式 69 個を読み込みました
  図面フォルダ/test2_1.svg
    矩形 20 / 円弧 19 / 線 50 (端点接続 78) / ... / 変換不能 0
    OLE部品 29 個を $$...$$ の数式として出力
  図面フォルダ/test2_2.svg   ...
  図面フォルダ/test2_3.svg   ...
  -> 図面フォルダ/test2.drawio (3 ページ)
```

引数を省略するとカレントフォルダを処理します。
`xxx.mdpf` と同じ名前の SVG が無い場合は、フォルダ内の他の mdpf と照合して相方を自動的に探します
（ファイル名を付け替えていても、OLE 部品の位置と大きさが一致すれば分かります）。


### 手作業で LaTeX を割り当てる（mdpf が無いとき）

画像ではなく LaTeX にしたい場合は、次の 3 段階で置き換えられます。
SVG に残っているのはラスタライズ済みの PNG だけなので、数式の構造（LaTeX）は
**中身を見て起こす**必要があります。

```bash
# 1. OLE 部品の画像を書き出して中身を確認する
python svg2drawio.py test.svg --dump-ole ole/

# 2. 対応表を書く (ole_latex.txt)。バックスラッシュはそのままでよい
#    52 = x_{ref}
#    96 = \frac{1}{M_d s^2 + D_d s + K_d}
#    97 = \Delta x

# 3. 数式として変換する
python svg2drawio.py test.svg --ole-latex ole_latex.txt -o test.drawio
```

`$$...$$` で囲んだテキスト部品として出力し、ファイルの数式組版（`math="1"`）を有効にします。
draw.io で開くとそのまま数式として組まれます（手動で有効化する場合は
**表示 > 数式組版**）。対応表は JSON（`{"52": "x_{ref}"}`）でも構いません。

### 大きさの調整

mdpf を渡した場合は**実寸**で配置します。SVG だけの場合は表示サイズが失われているため、**推定値**です。
`--ole-size`（数式 1 行分の高さ, mm, 既定 4.5）で全体を、`--ole-font`（px）で
数式モードの文字サイズだけを調整できます。個々の位置や大きさは draw.io 側で直せます。

## 変換精度

同じ図を「元の SVG」と「変換後の .drawio を draw.io 公式ビューアで描画したもの」の
両方を同一座標系で 1565×1099 px にレンダリングし、黒画素を 2px の許容で比較しています
（675 部品・576 テキストの制御ブロック図での実測）。

| | 割合 |
|---|---|
| 元図にあって変換後に無い画素 | 4.8% |
| 変換後にだけある画素 | 3.4% |
| 直交すべき線が斜めになった本数 | 0 / 213 |

残差はほぼ文字のアンチエイリアス差（1px 未満のにじみ）です。

## 既知の制限

- **開いた円弧**は完全な楕円になります（部分円弧の角度情報は使っていません）
- **曲線を含む線**は draw.io の `curved=1` による近似です
- **回転した矩形**は外接矩形になります
- コネクタは「線」として復元されるため、**元図の論理的な接続関係**（どの図形とどの図形が繋がっているか）は
  端点の位置から推定したものです。離れた位置で終わっている矢印は接続されず、座標固定のまま残ります
- 矢じりの形は draw.io の標準マーカー（`blockThin`）に置き換わるため、特殊な形状の矢印は見た目が変わります
- **SVG だけを渡した場合**、OLE 部品の表示サイズは復元できず（元の SVG に入っていないため）
  `--ole-size` による推定値になります。また LaTeX も自動生成できません。
  mdpf を一緒に渡せばどちらも解決します
- MTEF → LaTeX は常用構文（分数・上下付き・根号・括弧・ギリシャ文字・積分・総和）に対応。
  行列や未対応の記号に当たった数式は画像として復元します
- 対応している部品は矩形・円弧・多角線・OLE の 4 種類です。それ以外の部品を含む図では
  変換結果の最後に「変換不能」としてカウントされます

## 調整できるパラメータ

`svg2drawio.py` の冒頭にあります。

| 定数 | 既定値 | 意味 |
|---|---|---|
| `EQ_MARGIN` | `0.8` | 数式を枠のこの割合に収める (`--eq-margin` で変更可) |
| `SNAP_TOL` | `0.7` | 線の端点を図形に接続するときの許容距離 (mm) |
| `SMALL_SHAPE` | `4.0` | これ以下の大きさの図形は、内側で終わる線も接続扱いにする (mm) |
| `OLE_MM` | `4.5` | OLE 部品（数式など）の短辺の長さ (mm)。`--ole-size` で上書き |
| `PART_KINDS` | — | 部品名（日本語 / 英語）→ 図形の種類 |
| `FONT_MAP` | — | SVG のフォント名 → draw.io のフォント名 |
| `SYMBOL_MAP` | — | Adobe Symbol の文字 → Unicode |

## 関連プロジェクト

**汎用の SVG → draw.io 変換なら [svg-to-drawio](https://github.com/V1rg1lee/svg-to-drawio) を使ってください。**
transform・グラデーション・clip-path・マスク・画像埋め込みまで扱える、よくできた汎用ツールです。
本リポジトリは汎用変換を目指しておらず、**Dynamic Draw の出力に特化**することで忠実度を上げています。

同じサンプル（[examples/sample.svg](examples/sample.svg)）を両方で変換した結果です
（svg-to-drawio v3.10.1、2026-08-18 時点）。

![比較](docs/comparison.png)

| 観点 | 本ツール | svg-to-drawio |
|---|---|---|
| 元図とのピクセル差分（欠落 / 余分） | **6.4% / 5.8%** | 8.5% / 5.4% |
| コネクタ | **9 本**（折れ点・矢印つき、図形に接続） | 0 本（線も図形として出力） |
| 図形の種類 | ネイティブの矩形・楕円 | `shape=stencil(...)`（圧縮パス） |
| テキストのまとまり | 13 個（元の行構成のまま） | 18 個（入れ子 tspan が分裂: `K / (` `t` `s+1)`） |
| 上付き（e<sup>-Ls</sup>） | `<sup>` として復元 | `e` と `-Ls` が別セル |
| Symbol フォント（τ, μ） | Unicode に変換 | 元の文字コードのまま |
| 文字サイズ | 10.6px（元の 2.8mm と一致） | 6px |
| 意図しない折り返し | なし | 「制御対象」「Kp + Ki/s」が 2 行に割れる |
| ページサイズ | 元図の用紙サイズを設定 | 設定なし |
| 汎用性（transform・グラデーション等） | 非対応 | **対応** |

Dynamic Draw は「線の本体を矢じりの手前で止める」「部品種別をコメントに残す」「入れ子 tspan で
書体を切り替える」といった固有の癖があり、そこを知っているかどうかが差になっています。
逆に言えば、Dynamic Draw 以外の SVG では本ツールの優位性はありません。
